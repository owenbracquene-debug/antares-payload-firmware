# AnTARES Payload Firmware: Fluid Slosh Experiment

Flight firmware for the **fluid slosh payload** of [AnTARES](https://www.ugent.be), the student rocketry team of Ghent University, flying at **EuRoC 2026** (European Rocketry Challenge, Portugal).

The payload studies the in-flight behaviour of a liquid in a partially filled tank. A transparent pressure vessel, half-filled with a 40 % (w/w) glycerol–water blood analogue, is instrumented with pressure sensors and filmed by an onboard camera throughout the flight. The payload operates fully autonomously: it has no connection to the rocket avionics and detects launch on its own.

---

## System overview

| Subsystem | Hardware | Role |
|---|---|---|
| Main controller | STM32C092KCT6 (Cortex-M0+) | Sensor acquisition, launch detection, data logging, camera control |
| Inertial sensor | Bosch BNO055 (Adafruit breakout) | 3-axis acceleration, ±16 g range |
| Tank pressure | 2 × TE MS5837-30BA | Pressure and temperature of the fluid |
| Data storage | Winbond W25Q256JV (32 MB SPI NOR flash) | Non-volatile logging of all sensor data |
| Camera | Seeed Studio XIAO ESP32-S3 | Video recording of the tank, started on launch |
| Status indication | 3 LEDs | Pre-flight go/no-go check at a glance |

### Operating sequence

1. **Power-up:** LED start-up animation, sensor initialisation and self-check.
2. **On the pad:** continuous acquisition and logging, which provides a reference baseline for the pressure sensors.
3. **Launch detection:** when the total acceleration $|a| = \sqrt{a_x^2 + a_y^2 + a_z^2}$ stays above **3 g for 100 ms**, launch is confirmed. The sustained-threshold requirement rejects short shocks from handling.
4. **Camera start:** a `START` command is sent to the camera module over UART and retried until it is acknowledged.
5. **Flight and recovery:** acquisition and logging continue; the camera keeps recording.

## Hardware interfaces

### STM32C092 pin assignment

| Pin | Function | Connected to |
|---|---|---|
| PB7 / PB8 | I2C1 SDA / SCL | BNO055 (0x28), MS5837 #1 (0x76) |
| PA10 / PA11 | I2C2 SDA / SCL | MS5837 #2 (0x76) |
| PA0 / PA1 | USART1 TX / RX | XIAO ESP32-S3 (crossed RX/TX) |
| PA5 / PA6 / PA7 | SPI1 SCK / MISO / MOSI | W25Q256JV flash |
| PA4 | GPIO (chip select) | W25Q256JV /CS |
| PA8 | GPIO | W25Q256JV /RESET |
| PB0 / PB1 / PB2 | GPIO | Status LEDs 0 / 1 / 2 |

The MS5837 has a fixed I2C address, so the two pressure sensors are placed on separate I2C buses.

### Camera protocol (UART, 115200 baud, 8N1)

| Direction | Message | Meaning |
|---|---|---|
| STM32 → camera | `START\n` | Launch detected, start recording |
| Camera → STM32 | `ACK\n` | Command received, recording started |

### Status LEDs

| LED | State | Meaning |
|---|---|---|
| LED0 | Blinking (1 Hz) | Controller running |
| LED1 | On | All sensors responding correctly |
| LED1 | Fast blinking | Sensor fault |
| LED2 | Off | Waiting for launch |
| LED2 | On | Launch detected, camera acknowledged |
| LED2 | Fast blinking | Launch detected, but no acknowledgement from the camera |

## Sensor configuration

**BNO055.** Operated in accelerometer-only mode (`ACCONLY`) with the range set to **±16 g**. In the sensor-fusion modes the range is fixed at ±4 g, which would saturate during boost. Output resolution: 0.01 m/s² per LSB.

**MS5837-30BA.** Factory calibration coefficients are read from PROM and validated with the CRC-4 checksum. Raw pressure and temperature conversions (OSR 1024) are compensated using the first- and second-order algorithms from the datasheet. Output: pressure in Pa, temperature in 0.01 °C.

**W25Q256JV.** Accessed with the dedicated 4-byte address instructions, required because the capacity exceeds 16 MB. Data is appended sequentially and is never erased automatically at start-up, so a power cycle after landing cannot destroy flight data.

## Building and flashing

### Main controller (STM32)

**Requirements:** STM32CubeIDE 2.x, STM32CubeMX 6.18 or later, and an ST-LINK debugger.

1. In STM32CubeIDE, choose **File → Import → Existing Projects into Workspace** and select the `payload/` folder. Leave **"Copy projects into workspace"** unchecked.
2. Build the project with the hammer icon.
3. Connect the ST-LINK to the SWD header (SWDIO, SWCLK, GND, NRST, VDD_TARGET) and flash with **Run** or **Debug**.

To change pins or peripherals, edit `payload.ioc` in STM32CubeMX and regenerate the code. User code is kept between the `USER CODE BEGIN` / `USER CODE END` markers. Save `main.c` before regenerating.

### Camera module (XIAO ESP32-S3)

**Requirements:** Arduino IDE 2.x with the **esp32 by Espressif Systems** board package.

1. Open `esp_cam_arduino_code/esp_cam_arduino_code.ino`.
2. Select the board **XIAO_ESP32S3** and set **Tools → USB CDC On Boot → Enabled**.
3. Connect the board over USB-C and upload.
